# Настройка vps-afk

Скилл выносит работу на твой сервер, поэтому знать про сервер он должен от тебя.
Настраивается один раз, конфиг лежит вне репозитория и в git не попадает.

## Конфиг

`~/.config/claude-skills/vps-afk.env`:

```sh
VPS_AFK_HOST=пользователь@хост      # обязательно; должен пускать по ключу, без пароля
VPS_AFK_PROJECTS=projects           # куда разворачивать репозитории, путь от $HOME
VPS_AFK_RUNNER=skills/autonomous-loop/runner.py   # чем гонять работу, путь от $HOME
VPS_AFK_PLANS=.afk/plans         # куда класть план проекта
VPS_AFK_LOGS=.afk/runs           # где раннер держит логи
VPS_AFK_TOPICS=                     # необязательно: скрипт-уведомитель, пусто — шаг пропускается
VPS_AFK_STEPS=30                    # потолок шагов по умолчанию
VPS_AFK_HOURS=10                    # дедлайн прогона по умолчанию
```

Проверить, что путь до сервера рабочий: `ssh "$VPS_AFK_HOST" true` должно отработать
молча и мгновенно. Если спрашивает пароль — сначала `ssh-copy-id`, иначе ночью прогон
встанет на первом же запросе.

## Чего скилл ждёт от сервера

Свой раннер `vps-afk` не несёт — он запускает тот, что укажешь в `VPS_AFK_RUNNER`.
Раннер должен принимать флаги:

```
--project <имя> --repo <путь> --branch <ветка> --max-steps <N> --deadline-hours <N>
```

и работать сам, без вопросов: на сервере некому отвечать на запрос разрешения.

Кроме него на сервере нужны `git`, `python3`, `rsync` и пользовательский systemd
(`systemctl --user`) — прогон запускается через `systemd-run --user`, чтобы пережить
разрыв ssh. Проверить, что пользовательские юниты живут без активной сессии:

```sh
ssh "$VPS_AFK_HOST" 'loginctl show-user $USER -p Linger'
```

`Linger=no` означает, что после выхода из ssh systemd убьёт прогон — включается
командой `sudo loginctl enable-linger $USER` на сервере.

## Если сервера нет

Тогда этот скилл не нужен — бери [afk](../afk/SKILL.md), он держит работу на ноутбуке.
