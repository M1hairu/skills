# vault: второй мозг, который человек может открыть

`~/vault/` — обычные markdown-файлы, связанные `[[ссылками]]`. Человек клонирует
репозиторий и открывает папку в Obsidian: тот сам строит граф связей. Поэтому граф
строить не надо — надо **проставлять ссылки**, граф появится сам.

Это же хранилище живёт на сервере: агент там пишет в него из своих сессий. Синхронизация
идёт через приватный git-репозиторий, руками ничего копировать не нужно.

## Границы: что сюда не относится

Три хранилища, и они **не сливаются**:

| Где | Что | Кто пишет |
|---|---|---|
| `~/vault` | связное знание для человека | агент на ноутбуке и на сервере |
| `~/.claude/projects/*/memory` | короткие машинные факты для себя | Claude Code сам |
| `~/Documents/knowledge` | **личный волт человека** | только человек |

`~/Documents/knowledge` не трогать ни при каких условиях: не писать туда, не переносить
оттуда содержимое, не ставить ссылок между ним и `~/vault`. Он открывается как отдельный
волт Obsidian и к этой системе отношения не имеет.

Машинная память — тоже не то же самое: она привязана к путям и железу конкретной машины
и никуда не синхронизируется. Устойчивое и полезное человеку **поднимается** из неё сюда
пересказом, а не копированием файла.

## Главное правило: у каждого проекта один главный файл

```
vault/
  HOME.md                      точка входа: ссылки на все главные файлы
  projects/
    garmin-bot.md              ГЛАВНЫЙ файл проекта
    garmin-bot/                детали этого проекта
      voice-input.md
  systems/
    galaxy-book5.md
    galaxy-book5/
      audio.md
  people/
    mihail.md
  notes/                       знание, которое не привязано к одному проекту
    visual-language.md
```

**Главный файл проекта** — единственная точка входа. Всегда актуален, всегда отвечает
на четыре вопроса: что это, зачем нужно, в каком состоянии сейчас, что открыто.
Всё остальное — ссылки на детальные заметки. Если человек открыл главный файл и не понял
за минуту положение дел — файл плохой.

**Детальная заметка** заводится, когда: тема переросла два экрана, переиспользуется
из нескольких мест, или это самостоятельный сюжет (разбор формата, история инцидента,
устройство куска системы). Не дроби ради дробления: три абзаца живут в главном файле.

## Как писать

Frontmatter обязателен:

```markdown
---
type: project | system | person | note
status: активен | пауза | закрыт        # только для project
updated: 2026-08-12
---
```

Имена файлов — латиницей в kebab-case: `garmin-bot.md`, а не `Гармин Бот.md`.
Заголовок первой строкой после frontmatter — по-русски, как удобно читать.

Связи ставь щедро: `[[garmin-bot]]`, `[[galaxy-book5/audio]]`. Ссылка на ещё не написанную
заметку — нормально, это пометка «сюда стоит вернуться», Obsidian покажет её серой.
Именно из этих связей и вырастает граф.

Пиши так, чтобы человек понял без тебя: не «починил баг», а что было сломано, почему,
и как теперь. Даты — абсолютные, «вчера» через месяц бессмысленно.

**Секретам здесь не место**: токены, ключи, пароли — никогда, даже в примерах.
Адреса серверов и внутренние IP — тоже не надо: они меняются, а репозиторий уезжает наружу.

## Когда обновлять

- Узнал устойчивый факт о проекте или о человеке → в соответствующий файл, сразу.
- Начал новый проект → главный файл в `projects/` и строка в `HOME.md`.
- Факт устарел → **исправь на месте**, не копи слои. Важное изменение решения —
  строкой «было → стало → почему», остальное просто перепиши.
- Разовое, что не понадобится через неделю, — не пиши вовсе.

## Синхронизация

Делается командой, руками git трогать не нужно:

```bash
vault-sync            # подтянуть чужое и отправить своё
vault-sync --pull     # только подтянуть (в начале работы)
vault-sync --push     # только отправить (в конце)
vault-sync --status   # что не отправлено и насколько отстал
```

На ноутбуке это же делают хуки сессии: `SessionStart` тянет, `Stop` отправляет.
На сервере — таймер каждые полчаса. Настройка — `SETUP.md` рядом.

**Единственный случай, когда нужен человек:** правили один файл с двух машин
одновременно. Тогда `vault-sync` не станет чинить молча, а скажет про конфликт —
разбирать обычным `git pull --rebase` в `~/vault`.
