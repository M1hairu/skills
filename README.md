# Скиллы для работы без человека

Мой набор скиллов для [Claude Code](https://claude.com/claude-code): как оставить агента
работать на ночь или на день отсутствия и получить утром сделанную работу, а не оборванную
сессию.

Оборвать её могут четыре вещи: вопрос, на который некому ответить, запрос разрешения,
кончившийся лимит подписки и упавшая связь. Первое `afk` разбирает заранее, пока человек рядом;
второе снимает хуком прямо в идущей сессии, без перезапуска (а сессия, которую скилл заводит
сам, стартует в режиме, где разрешения не спрашивают вовсе); за двумя последними ночью следит
сторож `afk-watch` — ждёт сброса лимита или возвращения сети и поднимает работу с того места,
где она встала. Человек при этом не набирает ничего: он оставляет компьютер включённым.

## Установка

Два пути. **Симлинками** — репозиторий остаётся у тебя, правка файла действует в сессии сразу,
`git pull` обновляет всё разом; так это стоит у меня. **Плагином** — Claude Code держит у себя
копию и обновляет её сам, править нечего. Выбирай один: поставив оба, получишь каждый скилл
дважды.

<details>
<summary><strong>Симлинками (правишь под себя)</strong></summary>

```bash
git clone https://github.com/M1hairu/skills.git ~/Documents/skills
cd ~/Documents/skills
./install.sh
```

Какие скиллы:

```bash
./install.sh                 # все
./install.sh afk vps-afk     # только названные
./install.sh -i              # выбрать из списка по номерам
./install.sh --list          # посмотреть, что есть, и ничего не делать
```

Куда:

```bash
./install.sh                     # глобально, ~/.claude/skills — видно во всех проектах
./install.sh --local             # только в текущий проект, в его .claude/skills
./install.sh --project ~/код/x   # проект указан явно
./install.sh --agents            # заодно в ~/.agents/skills — Codex и другие харнессы
```

Ещё: `--dry-run` — вхолостую, `--force` — заменить мешающие файлы (старое уедет
в `~/.local/state/claude-skills/backups/<дата>/`), `--uninstall` — снять.

</details>

<details>
<summary><strong>Плагином (подписываешься на обновления)</strong></summary>

Из сессии Claude Code:

```
/plugin marketplace add M1hairu/skills
/plugin install m1x-skills@m1hairu
```

Скиллы приезжают read-only копией и обновляются вместе с репозиторием. Команды `afk`,
`stayawake`, `vps-afk`, `vault-sync` плагин в `$PATH` не кладёт — если нужны они, ставь
симлинками.

</details>

Требуется: `~/.local/bin` в `$PATH`, bash 4+, `git`, `python3`, `curl` и `tmux` — в нём `afk`
держит окно, чтобы оборванную сессию можно было разбудить, а не поднимать заново. Установщик
сам проверит, чего не хватает, и предложит доставить (`-y` — без вопроса). Команды рассчитаны
на Linux с systemd (`systemd-inhibit`, `systemd-run`); сами скиллы от системы не зависят.

## Справочник

### autonomy

**Model-invoked** — агент берётся за них сам, когда разговор к этому подходит.

- **[afk](./skills/autonomy/afk/SKILL.md)** — перевести идущую сессию в автономный режим на время
  отсутствия человека: собрать `PLAN.md`, вынести человеко-зависимое в `BLOCKED.md`, посчитать
  остаток лимита, выдать себе автономность и замкнуть цикл — всё сам, человеку набирать нечего.
  Команды скилла: `afk`, `stayawake`, `afk-limits` (остаток лимитов подписки), `afk-autonomy`
  (ночь без запросов разрешений, без перезапуска сессии), `afk-watch` (сторож, поднимающий
  работу после лимита и обрыва связи).
  [Подробнее](./docs/autonomy/afk.md).
- **[vps-afk](./skills/autonomy/vps-afk/SKILL.md)** — вынести работу на сервер и отпустить ноутбук:
  код через git, секреты по rsync мимо него, прогон под `systemd-run`, утром `git pull`.
  [Подробнее](./docs/autonomy/vps-afk.md), [настройка](./skills/autonomy/vps-afk/SETUP.md).

### memory

- **[vault](./skills/memory/vault/SKILL.md)** — хранилище знаний в `~/vault`: связные заметки
  о проектах, системах и людях, которые человек открывает в Obsidian; общие с сервером через
  приватный git, синхронизация командой `vault-sync` и хуками сессии.
  [Подробнее](./docs/memory/vault.md), [настройка](./skills/memory/vault/SETUP.md).

## Как это устроено

```
skills/<категория>/<имя>/
  SKILL.md      обязателен — сам скилл; каталог линкуется в <область>/skills/<имя>
  bin/*         команды скилла → по одной в ~/.local/bin/
  claude/*      файлы окружения Claude → в ~/.claude/
  SETUP.md      если скиллу нужна разовая настройка руками
```

Установщик работает по этому соглашению и не содержит перечня скиллов: новый скилл ставится
тем же `./install.sh`, править его не нужно. Команды и файлы окружения ставятся глобально
даже при `--local` — `$PATH` один на систему, а скрипты ищут окружение по путям от `$HOME`.

## Добавить скилл

```bash
./scripts/new-skill.sh autonomy/имя-скилла   # --bin, если нужна своя команда
$EDITOR skills/autonomy/имя-скилла/SKILL.md
./scripts/validate.sh
./install.sh имя-скилла
```

`validate.sh` держит репозиторий в форме: фронтматтер (`name` совпадает с каталогом,
`description` на месте и в пределах 1024 символов), синтаксис и права скриптов, инварианты
(скилл перечислен в `plugin.json`, упомянут в README, имеет страницу в `docs/`) — и ищет следы
личных данных: ключи, токены, адреса серверов, пути с чужим именем пользователя. Репозиторий
публичный, поэтому конфиги с адресами живут вне его, в `~/.config/claude-skills/`.

Соглашения репозитория — в [CLAUDE.md](./CLAUDE.md), решения и их причины —
в [.agents/adr/](./.agents/adr/).
