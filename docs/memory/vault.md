# vault

## Что делает

Держит связное знание о проектах, системах и людях в `~/vault` — обычных markdown-файлах
со ссылками `[[вот такими]]`, которые открываются в Obsidian как граф. Определяющее
ограничение: **это хранилище для человека, а не для агента.** Машинная память Claude Code
живёт отдельно и остаётся у каждой машины своей; сюда факт попадает пересказанным так,
чтобы человек понял его без агента.

Второе следствие того же: хранилище общее с сервером. Один приватный git-репозиторий,
две машины, обе пишут. Ноутбук синхронизируется хуками сессии, сервер — таймером.

## Когда за ним тянуться

Когда узнал устойчивый факт о проекте или о человеке; когда начал новый проект; когда
человека интересует «что ты вообще про это знаешь»; когда заметки расползлись и нужен
порядок.

Не для этого: разовые мелочи, живущие неделю (им место в машинной памяти или нигде),
и всё, что касается личного волта `~/Documents/knowledge` — его скилл не трогает вовсе.

## Частые вопросы

**Чем это отличается от памяти, которую Claude Code ведёт сам?**
Та память — короткие факты для агента, привязанные к путям и железу машины, и она никуда
не уезжает. Vault — связное знание для человека, общее между машинами. Одно не заменяет
другое, и файлы между ними не копируются.

**Что будет, если правили один и тот же файл на ноутбуке и на сервере?**
`vault-sync` не станет чинить это молча: он остановится и скажет про конфликт. Разбирается
обычным `git pull --rebase` в `~/vault`. Правки разных файлов сливаются сами.

**Почему заметки без адресов серверов и IP?**
Потому что они меняются, а репозиторий уезжает наружу. Адрес узнаётся запросом в момент,
когда он нужен; в заметке остаётся, как его узнать и как понять, тот ли он.

## Работает, если

Человек открыл `~/vault` в Obsidian, увидел граф и по главному файлу проекта за минуту
понял положение дел. Провал выглядит так: главный файл описывает состояние полугодовой
давности, детали дублируются в трёх заметках, а половина ссылок ведёт в пустоту, потому
что заметки переименовывали, а ссылки — нет.
